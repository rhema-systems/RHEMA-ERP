🚀 TO ADD NEW ENTITIES (Invoice, Customer, etc.):

  File: frontend/src/utils/notificationNavigation.ts
  
  Add to ENTITY_CONFIG:
  
    'Invoice': {
      displayName: 'Invoice',
      iconName: 'FileText',
      routePattern: '/finance/invoices/{id}',
      module: 'finance'
    }
  
  That's it! Everything else works automatically.

🔗 ENTITY CONFIGURATION FIELDS:

  displayName:    Human-readable name (e.g., "Invoice")
  iconName:       Lucide icon name (e.g., "FileText")
  routePattern:   URL pattern with {id} placeholder (e.g., "/finance/invoices/{id}")
  module:         Module grouping (e.g., "finance", "crm", "maintenance")

═══════════════════════════════════════════════════════════════════════════════

🛠️ ENTITY NAVIGATION FUNCTIONS:

  getEntityNavigationUrl(type, id)     → Get URL for navigation
  getEntityDisplayName(type)            → Get human-readable name
  getEntityIconName(type)               → Get Lucide icon name
  getEntityModule(type)                 → Get module grouping
  isNavigableEntity(type)               → Check if navigable
  getAvailableEntityTypes()             → List all entities
  getEntitiesByModule(module)           → Get entities for module
  registerEntity(type, config)          → Register dynamic entities
  getEntityConfiguration()              → Get full config

📊 DATA STRUCTURE:

  Notification {
    id: string
    recipientId: string
    notificationType: 'Email' | 'SMS' | 'Push' | 'InApp'
    title: string
    message: string
    priority: 'Low' | 'Normal' | 'High' | 'Critical'
    status: 'Pending' | 'Sent' | 'Failed' | 'Expired' | 'Cancelled'
    entityId: string           ← Link to specific entity
    entityType: string         ← Entity type (Invoice, JobCard, etc.)
    actionUrl?: string         ← (Computed by frontend)
    isRead: boolean
    createdAt: string
    attemptCount: number
    lastError?: string
    additionalData?: object
    tenantId: string
  }

🔌 API ENDPOINTS:

  GET    /api/notifications                    → Fetch with filters
  POST   /api/notifications/{id}/mark-read     → Mark as read
  POST   /api/notifications/mark-all-read      → Mark all as read
  DELETE /api/notifications/{id}               → Delete notification
  GET    /api/notifications/unread-count       → Get unread count
  SignalR /api/hubs/dashboard                  → Real-time events
