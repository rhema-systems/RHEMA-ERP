Quantity Survey end-to-end UAT — ordinary-user walkthrough

This script tells the tester exactly who signs in, where to go, what to click, what example value to enter, what result to expect, and what evidence to save. It follows one continuous example from project registration through BOQ, Works procurement, measurement, valuation, payment certificate, Finance AP handoff, variation, contractor claim, handover, defects, final account, and reports.

Use the deployed VPS address. The paths below start after the host name. For example, if the facilitator gives you https://your-vps-host, the Projects page is https://your-vps-host/development/projects. Do not use localhost for the VPS UAT.
Fresh-run rule. Use one run code in every title, note, and evidence filename. The worked example uses QS-UAT-20260930-01. If you already started that run, keep using it. For a new run, replace the date with the actual start date and increase only the final sequence when the code already exists. Never edit the preserved demonstration project PRJ-2026-0003.
Date rule. Project, phase, work-component, contract, measurement, certificate, and closeout dates must remain chronologically consistent. Tender deadlines, opening times, requisition required dates, payment due dates, and settlement dates must be valid when the step is executed. Do not copy an expired date merely because it appears in the worked example.
Field ownership rule. Maintain the phase schedule on the Phases tab. The work-component dialog asks only for Work Component Completion Weight (%), which is that component's share of progress inside its selected phase; it never asks the tester to enter a phase weight. The BOQ-line dialog owns Section, Trade, Cost Code, optional policy-controlled Measurement Code, Work Category / BOQ Item Type, and an optional Activity / Project Task link. Finance owns cost-centre assignment, so no cost-centre field is entered on a BOQ line.

How to follow each row

  1. Tick Done only after the expected result is visible.
  2. When the actor changes, sign out completely, sign in with the named username, and select tenant DEFAULT.
  3. Copy the example text and numbers exactly for this rehearsal. Pick the named controlled record from a selector; never type a database ID.
  4. After every create, submit, approve, post, or close action, write the generated reference in the Reference Log and take the requested screenshot.
  5. Click a mutation button once. If the page is slow, wait and refresh the record before trying again.
  6. If a named selector value is missing, a button is absent, or the expected status does not appear, stop that branch and record the visible message. Do not change roles, dates, database rows, or statuses to force it through.
