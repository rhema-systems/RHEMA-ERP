# HR Payroll Oracle Forms Migration Plan

## Source Artifacts

Legacy payroll artifacts are available under:

- `D:\PAYROLL\PAYROLL_RHEMA_DEMO`
- `D:\PAYROLL\PAYROLL_RHEMA_DEMO\Backup\pay.dmp`
- `D:\PAYROLL\Payroll_schema.txt`

Initial inspection found a full Oracle Forms payroll system with Forms, menus, PL/SQL procedures, reports, external import files, and a fresh logical backup. The schema contains 148 tables, 39 procedures, and 10 functions. The Forms folder includes payroll forms such as `PR3_*.fmb`, payroll reports such as `REP3_*.RDF`, payslip reports, menu files, libraries, CSV import templates, and GP/GL export scripts.

## Migration Decision

The current ERP HR module is the source of employee identity and employment master data only.

Do not reuse the existing HR salary/payroll-looking domain objects as the payroll implementation target, including:

- payroll flags on `Employee`
- contract salary fields
- employee salary assignments
- salary grades, levels, and notches

Those existing objects may remain in the system for now, but the migrated payroll module should define its own payroll-specific model based on the Oracle payroll app.

## Employee Reconciliation Rule

Payroll records should reference the ERP HR employee by `EmployeeId` and retain `EmployeeNumber` as the business/payroll number.

Oracle `HR_EMPLOYEES` should not become a second employee master. Its payroll-relevant fields should be mapped into payroll extension tables where needed:

- employee payroll eligibility
- PAYE/tax flags
- SSNIT/pension flags and numbers
- gross-up/non-resident/tier flags
- payroll currency
- payment method and bank details
- payroll salary basis
- legacy employee number mapping

The payroll module should expose a reconciliation screen that compares ERP employees against imported payroll employee references and highlights missing or mismatched employee numbers.

## Acceptance Rules

- ERP HR remains the employee master.
- Payroll uses its own tables and services for payroll-specific configuration and calculations.
- Every imported legacy employee reference must reconcile to an ERP `EmployeeId` or be reported as unmatched.
- Payroll runs must be repeatable in draft mode and immutable once closed.
- Payroll reports must be generated from saved run output, not recalculated live.
- Journal posting must preserve a clear audit trail from payroll run to finance entry.
