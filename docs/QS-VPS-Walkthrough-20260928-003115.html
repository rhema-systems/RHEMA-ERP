Quantity Survey end-to-end UAT walkthrough

Use this guide to run one complete, controlled Quantity Survey journey: project, approved BOQ, Works procurement/contract, measurement, valuation, certificate, variation, claim, handover and closeout. Every sign-in step names the account that should perform it. Passwords are deliberately not included here; enter them only in the sign-in page.

Read this first. This is a fresh-run script. Give every new record a unique prefix such as UAT-QS-<date>-<initials>. Do not reuse, edit, submit or approve the completed fixture unless you are demonstrating history. The preserved fixture is PRJ-2026-0003; its linked invoice stays Draft and must not be posted or paid.

How to use this script

  1. Use localhost:3000 and select the DEFAULT tenant after every sign-in.
  2. At each row, verify the expected result before moving on. Record the reference number and a screenshot in the UAT evidence pack.
  3. Sign out fully before changing actor. Opening a link does not change the signed-in user.
  4. Use the normal action shown by the page. Do not change a role, workflow, policy, database row or status to make a test pass.
  5. If a prerequisite is missing, stop at that row and record it as a UAT issue. Continue only with an independent part of the script.

F. Finance/AP boundary — record, do not bypass

The QS certificate is designed to create a source-linked Finance AP draft. Its posting, payment and reconciliation belong to Finance. These steps are part of the end-to-end design, but they are not currently ready in this UAT environment until Finance confirms the adopted-budget and AccountingBooks prerequisites.

If a step does not behave as expected

What you see What to do Do not do
Approve/submit button missing Confirm the signed-in username, DEFAULT tenant, record status and workflow assignment. Refresh once after a normal sign-in. Use admin or alter a role to bypass the assignment.
"Workflow required" or no valid route Record the process, exact message and screenshot. Administrator checks published workflow setup; the process owner decides the fix. Create a fake approval or change a status directly.
Contract/BOQ/measurement selector is empty Check project, tenant, active Works contract and approved BOQ prerequisites in order. Use a Supply contract or manually enter a foreign ID.
DMS file does not become clean Wait for scan status, refresh and retain the uploaded evidence record. Escalate an unavailable antivirus/scan service. Mark evidence complete without a clean scan.
Finance invoice cannot submit/post Stop at the Finance boundary and give the exact message to Finance. Preserve the linked Draft invoice. Create a replacement invoice, alter the QS certificate or record a payment manually.
Browser is slow or page times out Record time, URL and visible error; reload once. Verify backend/frontend availability before repeating a mutation. Click an action repeatedly; this can create duplicate requests.
Current known owner-gated prerequisites
  • Finance must resolve adopted-budget and AccountingBooks schema/configuration readiness before F2 posting/payment can be accepted.
  • Procurement and named owners must prepare, approve and publish the shared closeout configuration decisions; an empty draft is not a completed configuration.
  • The Works authority route must cover the actual contract value before initial/final takeover. Do not reduce a real value to fit an authority limit.
  • Retention release depends on applicable certificate, defect, takeover and Finance controls. The existing fixture has zero retention and must not be used to demonstrate a release.

UAT completion rule: mark a step Passed only after the expected status, record reference, correct actor and audit/history are visible. A green browser toast alone is not sufficient evidence for an approval, DMS upload, Finance handoff or closeout action.
