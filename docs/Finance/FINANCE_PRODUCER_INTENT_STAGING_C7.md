# Finance producer-intent staging (C7)

C7 gives owner modules a Finance-owned boundary for staging one neutral, balanced economic intent without selecting accounting books. For an original, Finance resolves the current C5 preview; a correction or reversal instead inherits its target's immutable frozen C5 hashes and ordered-book authority without consulting changed policy. Finance stores a complete canonical intent snapshot, binds it to the C6 request fingerprint, and keeps the request in `PendingApproval` until a different Finance user records an approval or rejection. Approval and rejection use that snapshot, never post, and remain possible when current C5 policy later drifts or blocks. The adapter remains disabled unless both the C7 and existing C6 feature gates are explicitly enabled.

Execution is a separate internal call. The public caller supplies no executable participant; a Finance-owned registry resolves the immutable identity to exactly one reviewed same-database handler bound to Finance's scoped `ApplicationDbContext`. The registry rejects missing/duplicate identities, another context, transaction-owning handlers, and external effects. Execution requires the exact approved snapshot, checker reason, source lineage, and participant identity. Finance freezes C5 inside C6's serializable transaction, invokes the handler under that exact ambient transaction, verifies the transaction was not replaced, and then creates each exact-book representation. A handler or Finance failure rolls the whole economic transaction back before C6 appends durable failure evidence. Exact retries recover through the same key and immutable request fingerprint; conflicting maker, checker, reason, participant, payload, snapshot, or lineage fails closed.

The handler contract deliberately exposes no book collection, applicability decision, posting leaf, transaction commit, or HTTP execution endpoint. Owners may only apply their already-staged same-database mutation when Finance invokes their registered handler. C5 remains the book-selection authority, C6 remains the group posting/reversal authority, direct posting callers retain current-actor retry authority and the C1 parallel-book rejection, and reversals continue to use the original frozen ordered book set.

`20260907190000_AddProducerIntentStagingC7` is an unapplied, additive migration. It refuses an absent/partial C6 base, adds producer decision and canonical snapshot evidence only to `AccountingEvents`, and installs complementary prepare-only insert, exact pending-to-decision, maker/checker, immutability, participant-identity, and approved-only execution guards. It does not enable either runtime gate.
