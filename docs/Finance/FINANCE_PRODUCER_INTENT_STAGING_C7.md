# Finance producer-intent staging (C7)

C7 gives owner modules a Finance-owned boundary for staging one neutral, balanced economic intent without selecting accounting books. For an original, Finance resolves the current C5 preview; a correction or reversal instead inherits its target's immutable frozen C5 hashes and ordered-book authority without consulting changed policy. Finance stores a complete canonical intent snapshot, binds it to the C6 request fingerprint, and keeps the request in `PendingApproval` until a different Finance user records an approval or rejection. Approval and rejection use that snapshot, never post, and remain possible when current C5 policy later drifts or blocks. The adapter remains disabled unless both the C7 and existing C6 feature gates are explicitly enabled.

Execution is a separate internal call with no callback, registry, delegate, or exposed context. A later reviewed owner service must begin a transaction on the same scoped `ApplicationDbContext`, stage its owner mutation, and provide a deterministic receipt matching the immutable expected participant, owner entity, action, and effect fingerprint prepared with the intent. Finance refuses a missing, committed, disposed, or replaced ambient transaction and never starts, commits, rolls back, or disposes the owner's transaction. It persists the unique immutable receipt, freezes C5, and creates the exact-book representations inside that transaction. The owner service rolls back on failure, then invokes the separate post-rollback Finance boundary to append durable failure evidence. Exact retries recover through the same key, receipt, and request fingerprint; conflicting maker, checker, reason, receipt, payload, snapshot, or lineage fails closed.

The internal contract exposes no book collection, applicability decision, posting leaf, transaction control, arbitrary executable code, or HTTP execution endpoint. C7 does not pretend to police arbitrary owner C# or external I/O: preventing external effects is an owner-code review obligation, while this boundary itself only accepts data and performs Finance-owned database work. C5 remains the book-selection authority, C6 remains the group posting/reversal authority, direct posting callers retain current-actor retry authority and the C1 parallel-book rejection, and reversals continue to use the original frozen ordered book set.

`20260907190000_AddProducerIntentStagingC7` is an unapplied, additive migration. It refuses an absent/partial C6 base, adds producer decision/canonical snapshot evidence and the immutable `AccountingEventProducerReceipts` authority, and installs complementary prepare-only insert, exact pending-to-decision, maker/checker, receipt uniqueness/immutability, participant-identity, and approved-only execution guards. Its `Down` refuses either decision or receipt evidence. It does not enable either runtime gate.
