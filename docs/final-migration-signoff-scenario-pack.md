# Final Migration Sign-Off Scenario Pack and Go/No-Go Evidence Foundation

## Scope

This batch adds a backend dry-run/UAT sign-off evidence pack.

It does not execute final production migration, mark production go-live approved, create posted accounting, or redesign reversal/correction workflows.

## Sign-Off Run Model

No persistent sign-off run table was added in this batch.

The run is an auditable DTO/report output generated by `IMigrationSignOffService.RunFinalMigrationSignOffAsync`.

This is intentional for the foundation stage:

- production sign-off evidence is not yet being executed;
- the run creates no journals;
- the run mutates no posted GL;
- the output is repeatable per tenant and cutover date;
- audit events record run start, completion, failure, evidence generation, limitation decisions, blocking findings, and review.

If production requires long-lived sign-off run history inside the ERP database, that should be implemented with the actual production sign-off execution workflow.

## API Surface

`MigrationSignOffController` exposes:

- `POST /api/finance/migration-signoff/final-signoff/run`
- `POST /api/finance/migration-signoff/final-signoff/review`

Existing tooling endpoints remain:

- posting back-reference diagnostics/repair;
- bank snapshot diagnostics/rebuild;
- subledger opening migration scope.

## Run Statuses

The sign-off run returns:

- `Passed`
- `PassedWithAcceptedLimitations`
- `Failed`

`Failed` is returned when the run finds blocking diagnostics or unaccepted go-live-blocking limitations.

`PassedWithAcceptedLimitations` is returned only when accounting checks pass but open limitations are marked accepted non-blocking or not applicable for the tenant/cutover.

## Checks Implemented

The sign-off pack checks:

- posted GL trial balance debit/credit balance;
- posted, balanced, referenced opening-balance batches;
- unposted or failed opening-balance batches;
- duplicate opening-balance posting events;
- posting back-reference diagnostic gaps;
- bank snapshot variance against posted GL movement;
- AP settlement read-model diagnostics and AP control account variance;
- AR settlement read-model diagnostics and AR control account variance;
- fixed asset missing posting references;
- disposed/written-off fixed assets with nonzero NBV;
- completed fixed asset disposals missing posting references;
- negative fixed asset book values;
- active current COVID-19 levy configuration;
- tax snapshots referencing missing tax configuration;
- tax snapshots missing posted GL source lines;
- pending workflow instances;
- legacy direct posting or `ALL_ACTIVE_BOOKS` posting evidence.

## FIN-LIM-0048 Cutover Data Shape

The sign-off request explicitly declares whether the cutover includes:

- open AP supplier invoices;
- open AR customer invoices;
- unapplied AP payments or supplier advances;
- unapplied AR receipts or customer advances;
- fixed asset opening register balances;
- WHT/VAT withholding certificate balances;
- foreign-currency AP/AR open balances;
- bank balances requiring cashbook detail.

If none of the AP/AR/fixed-asset subledger opening balances are in scope, `FIN-LIM-0048` is marked not applicable for that tenant run.

If source-level subledger openings are required, `FIN-LIM-0048` blocks final sign-off until those balances are loaded through posted source-document/import paths that reconcile to GL.

GL-only opening balances must not be used to fake AP/AR aging or fixed asset register balances.

## Permissions

The Finance permission policy map routes:

- sign-off run and diagnostics to `Finance.Migration.Diagnostics.Run`;
- repair/rebuild and sign-off review to `Finance.Migration.Adjustments.Run`.

Existing repair/rebuild audit events are also emitted when the sign-off pack invokes diagnostic tooling.

## Rollback And Reset

The sign-off run itself creates no accounting records.

Rollback considerations:

- no schema rollback is required for this batch;
- rerunning the sign-off pack is safe;
- bank snapshot rebuild remains read-side only;
- posting back-reference repair mutates only unambiguous source-document back-reference fields;
- posted GL changes still require controlled reversal or dev/UAT environment reset.
