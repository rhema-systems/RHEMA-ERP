# Finance integration regression evidence

Scope: Finance changes integrated into master through `b8307938eb`, including canonical Business Partner roles/profiles. Started 2026-09-27 after the missing Accounts tabs report. This is an acceptance checklist, not a claim that all flows pass.

## Confirmed findings

- Supplier/customer Accounts tabs were removed in the Finance integration. The new restoration displays current account sources; it does not restore all historical GP-style editable partner overrides.
- BusinessPartnerService still persists legacy posting/receivables defaults, but saving a field does not prove current transactions use it.
- Canonical AP profiles support expense/tax/payment/WHT configuration. Canonical AR profiles do not currently provide the full historical GP-style GL account mappings.
- Normal AR invoice posting uses central AR/inventory/COGS settings and invoice revenue lines. The audited Sales credit-note fix now retains the original linked invoice's AR control account, or central AR for standalone notes. Sales Returns contra and receipt accrual/PPV still have separate, documented account-source policies.
- Corrected AP profile UI saves that omitted expense/tax defaults and reactivated inactive WHT rows. Version selection and unsaved submission are explicit. Server validation checks tenant, activity, applicability and account eligibility; multi-save AP profile writes are transactional.
- Corrected AP/AR invoice date changes retaining stale captured profile IDs; AR terms/credit projections reading legacy partner fields; AP role-specific payment terms comparing against a display label; AP first posting omitting captured-profile readiness; and AP expense fallback reading the legacy supplier field. Backend execution evidence is recorded below when available.
- Historical AP expense retries use original posted account evidence. A posted custom distribution whose original basis is missing or changed stops with `AP_INVOICE_DISTRIBUTION_HISTORY_REQUIRED`; the fix does not invent historical accounts or reset a posted distribution.
- No complete cross-module transaction regression run has been performed for this change. Restored tabs or a successful build alone are insufficient acceptance evidence.
