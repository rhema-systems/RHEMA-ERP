# Supplier invoice cost differences and supplier returns — requirements 8–9

Status: implementation plan based on current source inspection on 2026-09-27. No financial settings, runtime, database or posting code were changed for this analysis. Existing tests listed below were inspected, not executed in this task. This plan does not mark either requirement complete.

## Required result

Requirement 8 adds the Procurement company policy **Revalue Inventory / Post to Purchase Price Variance** when an invoice differs from its accepted GRN. Original receipt cost remains immutable. Price differences must be allocated by actual invoiced receipt quantity, with tax and currency effects treated separately, and replay must not repeat either valuation or GL.

Requirement 9 allocates each returned quantity to its original receipt and, where posted, original invoice line. Uninvoiced quantities reverse their receipt accrual. Invoiced quantities use the existing AP debit-note owner and subledger; shipping goods does not itself authorize an AP credit. The example of 100 received, 60 invoiced, 50 returned requires a provable 40 uninvoiced / 10 invoiced split when those are the remaining eligible quantities.

## Bounded implementation sequence

### 1. Shared receipt accounting evidence and locks

Create a read-only planner in the existing Procurement/AP boundary, backed by the existing accepted-supply and receipt-allocation owners. It returns exact source IDs, purchased/base quantities, immutable UOM conversion, accepted quantity, posted invoice shares, unposted reservations, prior returns, original receipt inventory/accrual journal lines and amounts, and original currency/rate evidence. Define one deterministic lock order reused by invoice generation/post/void and return draft/dispatch/credit: sorted PO matching locks, sorted GRN source locks, document mutation locks and AP settlement locks in one reviewed order. Audit all current callers before changing the order.

Current invoice posting already uses `tdc-ap-match:{tenant}:{po}` then `supplier-return-source:{tenant}:{grn}`; return draft uses the GRN source lock and return dispatch uses `supplier-return:{tenant}:{return}`. The source planner must not introduce opposite-order waits or evaluate invoice stage outside the relevant lock. Maintain serializable transactions and retry/reset behavior.

Do not reconstruct ambiguous historical invoice-to-GRN cost shares from current costs. Preserve those documents and return an actionable reconciliation requirement. Existing provable single-account/line cases can be supported without rewriting history.

### 2. Invoice policy, immutable variance allocation and common distribution

Add a validated policy enum through Procurement settings and its existing configuration snapshot/version flow. Posted history has no retroactive policy assignment. For existing unposted documents, resolve and snapshot the configured policy when the cost plan is accepted; invalidate saved distribution when policy or source basis changes. If policy configuration is absent, require configuration before posting a nonzero difference rather than silently selecting a new accounting policy.

Retain per-allocation evidence sufficient to reproduce: invoice and invoice line, receipt/GRN line, invoiced purchase/base quantity, receipt original accrual amount/account, invoice commercial net amount after existing trade-discount allocation, signed price difference, separate currency effect, policy, eligible remaining-stock quantity, Inventory/PPV account IDs, valuation movement/layer targets, posting event/journal and reversal linkage. Reuse existing quantity allocation and add only missing evidence/detail fields or dependent records.

For the supplied same-currency example, invoice distribution must be Dr original GRNI 1,000 + Dr PPV or eligible Inventory adjustment 100 + original invoice tax lines / Cr AP at the invoice total. A negative price difference credits its difference target. Original GRN and original receipt journal remain unchanged. Base quantities and document-currency quantities cannot be mixed. Use existing `MonetaryAllocation` and Finance currency precision so partial allocations sum to the original amount; the last allocation takes the exact residual.

Under **PPV**, use each item's configured PPV account. Under **Revalue**, value only proved remaining original receipt stock. FIFO needs remaining source-layer evidence; WAC needs a documented receipt-quantity consumption allocation rule rather than `balance > 0`. Standard-cost behavior must follow its current standard-cost rules, routing unsupported revaluation to configured variance. Transfer/reclassification/consignment changes require traceable original-cost lineage: current transfer legs retain carrying value but are not, by themselves, a complete per-receipt FIFO-consumption genealogy. Extend that lineage where required; otherwise block ambiguous revaluation and show the exact reason. Do not label untraceable still-owned transferred stock as consumed.

Consumed/sold/issued quantities go to configured PPV according to the selected policy's documented residual treatment. Reject negative resulting layer/balance values. Use quantity-zero cost-adjustment movements and no extra quantity receipt/issue. Both GL and valuation commit or roll back together. Coordinate currency treatment with existing Finance source rates: do not relabel receipt-to-invoice FX changes as purchase-price variance or translate original accrual at today's rate. Missing original currency evidence is a reconciliation blocker.

Add the protected posting purposes to the existing Distribution preview/save/post path. Keep editable expense splits where already supported; users must not erase or redirect required original-accrual, Inventory, PPV, tax or AP source authority. Freeze the same dimensions and source basis as the posted plan. Void/reversal must compensate the original adjustment from retained evidence, accounting for subsequent consumption; it must never recompute from current policy/accounts.

### 3. Return allocations and financial completion

For each returned GRN line, compute remaining uninvoiced accepted quantity after existing posted/unposted invoice reservations and prior return claims. Allocate the uninvoiced eligible portion first when the documented source rules permit; allocate the rest to exact posted invoice receipt shares, deterministically and visibly. Preserve user review when more than one legitimate original invoice exists. Invoice drafts that reserve those quantities must be reconciled or released, not silently converted into posted AP quantities.

Persist immutable dispatch-stage accounting allocations. Split actual physical carrying value across them once, using existing exact monetary allocation. For an uninvoiced slice, debit its original receipt accrual basis and credit actual Inventory carrying value, with a separately explained configured difference if those bases no longer agree. For an invoiced slice, reuse existing Dr RTV clearing / Cr Inventory dispatch and later AP debit-note clearing/variance treatment. Never debit AP directly from the Inventory service.

Group invoiced slices by original invoice/currency/credit context into separate debit-note drafts. Replace the return-wide unique note restriction with allocation/group uniqueness; each allocation can be claimed once, each group has a stable replay key, and each note retains exact original invoice-line references. Preserve the current protection against already-paid/reserved invoice capacity; additional supplier credit/refund handling is a Finance decision and must not be faked by reducing PaidAmount or bypassing AP settlement.

Return status displays physical dispatch and each financial completion separately. The source selector and detail screen show the split, original invoices, clearing/accrual journals and all debit notes. Cancelled drafts release only their own reservations; posted quantities are reversed through governed compensating documents. The legacy Finance SupplierReturns route is not a substitute for the canonical Inventory return owner.
