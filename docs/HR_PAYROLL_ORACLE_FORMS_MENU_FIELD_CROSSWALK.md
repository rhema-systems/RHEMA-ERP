# HR Payroll Oracle Forms Menu and Field Crosswalk

## Extraction Notes

The left-side menu shown in the Oracle Forms screenshots is generated by `APP_MENU_FRM.fmb`, not by the `.mmb` files alone.

Evidence found:

- `APP_MENU_FRM.fmb` sets the window title to `Application Main Menu - PAYROLL`.
- `APP_MENU_FRM.fmb` loads the hierarchy from `APP_MENU_DISPLAY`, filtered by `APP_MENU_SECURITY`.
- `DUMP.DMP` contains the `APP_MENU_DISPLAY` rows, including menu id, sequence, form code, caption, parent menu, and company scope.
- `SECURITY_MENU.mmb` contains static menu/security entry points and an access procedure, but it does not contain the full screenshot tree.

The ERP payroll module should therefore use `APP_MENU_DISPLAY` as the navigation source of truth and use each `MND_MENU_SYSTEM_NAME` to locate the matching `.fmb` form and `.fmx` runtime file.

## ERP Build Implications

- The Administration payroll page should follow `Main Menu > Setup`, not the earlier generic setup tabs.
- The HR payroll page should follow `Main Menu > Payroll Process`, `Payroll Administration`, and `Payroll Reports`.
- `Codes Description` must be implemented from `GE3_004` / `APP_CODES_TABLE` / `APP_CODES_DESC`; `GE3_003` belongs to menu maintenance.
- Salary Advance is period-aware through date range, not by storing pay period on the input row. Oracle `PAY_SALARY_ADVANCE` stores `SAL_ADVANCE_DATE`, employee, amount, description, and company; `PRC_SALARY_ADVANCE` filters `SAL_ADVANCE_DATE` between `APPS_PARAMETERS.PAR_PAY_PERIOD_FM` and `PAR_PAY_PERIOD_TO`, then stamps `PRL_PAY_PERIOD`, `PRL_PAY_PERIOD_FM`, and `PRL_PAY_PERIOD_TO` on `PAYROLL_TRANSACTION`. The Oracle reset flow treats `PAY_SALARY_ADVANCE` as current-period input, deletes/truncates the input rows after payroll, and advances `APPS_PARAMETERS.PAR_PAY_PERIOD_FM`, `PAR_PAY_PERIOD_TO`, and `PAR_PAY_PERIOD` for the next cycle.
- Salary Advance (`A0000203` / `PR3_012.fmb`) and Loan Transaction (`A0000204` / `PR3_013.fmb`) are standalone payroll process screens under HR > Payroll, not tabs under the payroll run desk.
- Loan Transaction Amendment is a standalone payroll process screen (`A0000205` / `PR3_013A.fmb`), not a tab under the payroll run desk. It searches existing `PAY_LOAN_TRANSACTIONS` rows, then amends balance, repayment, interest, status, suspension, narration, and remarks fields.
- Loan Repayment is a standalone payroll process screen (`A0000206` / `PR3_015.fmb`). It is schedule-driven: Oracle selects the next unpaid active `PAY_REPAYMENT_SCHEDULE` row by facility/loan sequence, records `REP_AMOUNT_PAID`, `REP_INTEREST_PAID`, and `REP_ACTUAL_REPAYMENT_DATE`, and refreshes the loan balance/cumulative repayment state.
- Company-scoped rows such as `BUCK`, `GBC`, `DEMO`, `PHC`, and `LIBHJ` are still real menu items in the dump. Treat them as migrated legacy capabilities unless a tenant-specific rollout intentionally hides them.
- ERP HR stays the employee master; forms `PR3_005` and `PR3_005A` provide payroll extension fields, not a second employee master.
