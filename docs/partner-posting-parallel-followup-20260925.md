## Implemented changes

- Supplier input tax: opted-in invoices capture the supplier input-tax fallback account. An explicit tax-rule receivable account takes precedence. The fallback applies only to recoverable input tax; nonrecoverable tax retains the existing expense/fixed-asset treatment. New fallbacks must be active, postable Asset/Liability accounts in the same tenant. Existing legacy partner mappings are retained on unrelated edits. Existing invoices without a captured fallback retain their former behavior.
- Supplier write-offs: an explicit standalone debit-note line type uses the supplier Writeoffs account unless the user selects an override. The draft captures the resolved account. Posting debits AP and credits the captured Revenue/Expense account through the existing debit-note approval/posting engine. Retry and reversal follow that document's existing controls. The line cannot carry source-invoice links, tax or discounts. It reduces overall AP and creates an available supplier credit; applying that credit to outstanding invoices is a separate settlement step. It does not automatically clear an invoice, write off advances, or implement customer bad debts.
- Debit-note form: exposes an explicit credit classification, retains it when reopening drafts, and offers the supplier Writeoffs fallback. Choosing a write-off clears tax/discount inputs and requires approval/posting through the normal document process.
- Customer verification: additional tests save and reload mappings through the real partner service/repository before invoice, receipt and governed return-credit preparation assertions. These tests do not replace relational or browser lifecycle acceptance.
- Posting retries: AP discount and AR default-account choices now recover original posted account evidence when rebuilding an already posted request. AP verifies the tenant, AP source document and posted unreversed journal, then requires one original discount account. AR verifies the corresponding event and journal before resolving control, sales, cost, inventory or receipt-discount roles; revenue/cost roles retain source-line identity. Explicit invoice GL accounts remain authoritative. The central engine still validates the full canonical request, so changed document amounts/accounts/dimensions are not silently accepted. This avoids redirecting a retry after a later master-default change; original account/book/period validation remains enforced.
- Account selector audit: all 11 visible AP account rows and all six AR rows have source posting consumers. The supplier cheque-book field is now hidden on customer-only Options, retaining saved mappings and supplier/contractor/dual-role visibility. Contractor details now expose AP consistently with the editor. The Writeoffs picker restricts new choices to Revenue/Expense, matching posting validation, while retaining unsupported existing selections until explicitly changed. Trade Discount and Terms Discounts Available are not displayed account rows; the existing net-trade/recognize-discount-when-taken policies remain. Unsupported GP customer cash/charge/write-off roles are not presented as working AR settings.
