## Default scope

Core preparation, measurements, valuations/certificates, variations/claims, contract costs, retention, audit and reporting remain accessible through the existing Projects and shared-owner screens. Standard BOQ entry/import and Procurement bid-item entry remain available.

The default QS journey hides joint-signature workspaces, dayworks, subcontract/back-charge workspaces, price-index/escalation screens, separate design-impact analysis, specialised tender exchange/vetting, external QS submission tabs, standalone advance-recovery setup and final-account workflow entry. Existing payment deductions, contract balances, Finance records and historical data remain intact. Shared Procurement/Contracts features are not removed from their owning modules.

`frontend/src/lib/quantity-survey-architecture-scope.ts` centralizes visibility. `NEXT_PUBLIC_QS_OPTIONAL_FEATURES` is an explicit, comma-separated deployment opt-in using the documented keys in that file; absent/empty means core scope. It is not an authorization grant. Optional configuration decisions 006, 013, 014 and 017 are hidden from the default register; administrators can reveal them, and evidence history remains visible.

Automatic external tender-BOQ intake is also optional on the API: `QuantitySurvey:OptionalFeatures` (environment key `QuantitySurvey__OptionalFeatures`) must include `external-submissions` for new ordinary Procurement bids to enter that additional QS exchange. Enable the matching frontend key when deploying the extension. Existing QS submission records retain their reconciliation and rejection checks even after the opt-in is removed; tenant/partner ownership, procurement eligibility, document issuance and sealed-bid controls remain enforced. Explicit specialised exchange APIs and retained records remain available to their existing authorized owners.

Profiles now publish only their configured decisions, instead of requiring all 17 questionnaire decisions. Blank placeholders are not blockers; malformed, unapproved, undated or unsupported configured values still fail validation. An empty profile is not publishable. Operations retain validation for the processes they actually use. New internal valuations omit external submission controls when the API `external-submissions` opt-in is off, including copied policy values. Enabling the extension retains configured contractor/consultant requirements. Existing worksheets retain their frozen internal/external scope across deployment changes. Supporting measurement evidence and independent approval remain enforced.
